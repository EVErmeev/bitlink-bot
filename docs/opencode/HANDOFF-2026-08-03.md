## Архитектура приложения

```
Локальный TXT/MD
  → ProcessingService.process_item()
    → _load_transcript()
    → LLMClient.generate_json() (OneBitNewtonCLIProvider → newton.cmd summarize)
    → template.assemble_from_llm_json()
    → protocol_register_extractor (отдельный LLM pass для реестров)
    → техническая валидация (HTML render)
    → quality check (PROTOCOL_QUALITY_MODE=advisory)
    → Confluence REST API (create_page)
    → Telegram Bot API (sendMessage)
```

## Рабочий pipeline (подтверждён)

1. TXT/MD загружается
2. LLM генерирует протокол (Newton CLI summarization)
3. Шаблон собирает Protocol и рендерит HTML
4. Протокол публикуется в Confluence
5. Telegram-уведомление отправляется
6. Статус: `completed` или `completed_with_warnings`

## Как выполнять независимую проверку

1. Запустить `call start_app.bat`
2. Добавить локальный TXT в очередь
3. Нажать «Запустить обработку»
4. Проверить: прохождение стадий, отсутствие traceback в терминале, статус `completed`
5. Двойной клик по строке → открыть Confluence
6. Проверить заголовок, дату, реестры
7. Проверить Telegram — сообщение с ссылкой
8. Сравнить с последними результатами в этом документе

## Что нельзя повторно переделывать

- Pipeline доставки (TXT → LLM → Confluence → Telegram) — работает
- Настройки Newton/Confluence/Telegram — настроены и проходят проверки
- PROTOCOL_QUALITY_MODE=advisory — не менять без подтверждённого дефекта
- Единый Newton CLI (token/path) — не дублировать настройки
