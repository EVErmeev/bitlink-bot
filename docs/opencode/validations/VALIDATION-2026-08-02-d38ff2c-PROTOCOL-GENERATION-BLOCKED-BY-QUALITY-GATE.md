\#\# Вердикт

\`CHANGES\_REQUIRED\`

Сбой вызван не недоступностью нейросети и не отсутствием результата генерации. Нейросеть вызывается, JSON протокола собирается, HTML рендерится, после чего отдельный Quality Gate блокирует готовый результат по внутренним формальным правилам.

Ожидаемый пользовательский сценарий:

\`\`\`text  
расшифровка  
→ выбранная нейросеть  
→ выбранный шаблон  
→ готовый протокол  
\`\`\`

Фактический сценарий:

\`\`\`text  
расшифровка  
→ LLM  
→ Protocol  
→ HTML  
→ structure\_validation  
→ render\_validation  
→ validation\_failed  
\`\`\`

\#\# Подтверждённые дефекты

\#\#\# BB-CRIT-115 — Quality Gate блокирует готовый протокол

\`ProcessingService.process\_item()\` требует, чтобы одновременно прошли:

\- source alignment;  
\- fact validation;  
\- structure validation;  
\- render validation;  
\- topic coverage;  
\- topic alignment.

Любая ошибка переводит элемент очереди в \`validation\_failed\`, даже если LLM успешно ответила, JSON распарсен, Protocol сформирован и HTML создан.

\#\#\# BB-CRIT-116 — LLM-массивы решений, вопросов, рисков и задач разбираются неполно

\`assemble\_from\_llm\_json()\` полноценно разбирает тематические блоки, но не преобразует все поля массивов \`decisions\`, \`questions\`, \`risks\`, \`tasks\` в модели протокола. Затем \`\_fill\_from\_atomic\_items()\` создаёт упрощённые объекты.

Для решения остаётся пустым \`context\_and\_basis\`, после чего валидатор сам блокирует протокол:

\`\`\`text  
assembler оставил поле пустым  
→ validator запретил пустое поле  
→ протокол получил validation\_failed  
\`\`\`

\#\#\# BB-CRIT-117 — противоречащие пороги тематического раздела

Структурная проверка допускает тематический раздел от 20%, а HTML-проверка требует не менее 55%. Порог 55% является субъективным требованием версии шаблона, а не техническим условием корректного HTML.

Результат 30.9% не означает, что протокол сломан.

\#\#\# BB-CRIT-118 — успешная генерация маркируется как ошибка

После render код устанавливает:

\`\`\`text  
result\["error"\] \= "Protocol validation failed \- publication blocked"  
item.status \= "validation\_failed"  
result\["success"\] \= False  
\`\`\`

Пользователь видит ошибку, хотя результат уже сформирован.

\#\#\# BB-MAJ-119 — technical checks и quality checks не разделены

Блокирующими должны быть только технические ошибки:

\- пустой источник;  
\- LLM недоступна;  
\- LLM не вернула результат;  
\- JSON невозможно разобрать после попыток исправления;  
\- Protocol невозможно собрать;  
\- HTML невозможно сформировать;  
\- артефакты невозможно сохранить.

Проверки качества не должны блокировать результат по умолчанию:

\- доля тематического раздела;  
\- краткость разделов;  
\- пустая дополнительная ячейка;  
\- отсутствующие участники;  
\- недостаточная evidence;  
\- внутренние пороги количества слов.

\#\#\# BB-MAJ-120 — автоматические коррекции непрозрачно меняют результат LLM

После генерации вызываются \`validate\_facts()\` и \`apply\_corrections()\`. Пользователь не видит, что было изменено и по какому правилу. В обычном режиме результат выбранной нейросети не должен переписываться без прозрачного отчёта.

\#\#\# BB-MAJ-121 — нет режима проверки качества

Необходимо добавить:

\`\`\`text  
PROTOCOL\_QUALITY\_MODE=off|advisory|strict  
\`\`\`

По умолчанию: \`advisory\`.

\#\#\# BB-MAJ-122 — UI скрывает сформированные артефакты

При \`validation\_failed\` пользователь всё равно должен иметь доступ к:

\- \`protocol.json\`;  
\- \`protocol\_preview.html\`;  
\- ответу LLM;  
\- отчёту качества.

\#\# Целевая модель

\`\`\`text  
ТЕХНИЧЕСКАЯ ГЕНЕРАЦИЯ

Расшифровка  
→ выбранный шаблон  
→ выбранная LLM  
→ schema-valid JSON  
→ Protocol  
→ HTML  
→ сохранение артефактов  
→ completed

ОЦЕНКА КАЧЕСТВА

Готовый Protocol  
→ необязательные quality checks  
→ warnings / quality report  
→ не отменяют completed  
\`\`\`

\#\# Рекомендуемые статусы

\- \`completed\` — протокол сформирован без предупреждений.  
\- \`completed\_with\_warnings\` — протокол сформирован, но есть рекомендации.  
\- \`failed\` — техническая невозможность получить протокол.  
\- \`validation\_failed\` — только в явно выбранном строгом режиме.

\#\# Итог

Проблема воспроизводится архитектурно и не зависит от конкретной расшифровки.

Основной дефект:

\> приложение уже получило результат нейросети, но затем отменило успешную обработку из\-за субъективных внутренних правил шаблона.

Следующая итерация должна сделать Quality Gate рекомендательным по умолчанию и сохранить результат нейросети как основной артефакт.
