\#\# 2\. Дефекты \`project\_detailed\`

\#\#\# Название протокола

Оно всё ещё содержит лишний абзац, похожий на summary. Требуется короткая одна строка: 6–14 слов, максимум 120 символов, без имени файла и без перечисления итогов. Summary должно быть отдельным полем.

\#\#\# Клиент и проект

В модели и UI нет надёжного источника \`client\_name\` и \`project\_name\`. Нельзя заставлять LLM придумывать их. Нужны отдельные пользовательские поля.

\#\#\# Ключевые итоги

\`key\_outcomes\` остаётся строкой, поэтому выводится как сплошной текст. Требуется \`array\[string\]\` и HTML-список.

\#\#\# Тематические блоки

\`discussion\_content\` остаётся одной строкой. Renderer только заменяет переносы на \`\<br\>\`. Требуются отдельные подпункты: текущее состояние, проблемы, обсуждение, варианты, аргументы, вывод, статус, следующие действия.

\#\#\# Текущее состояние

\`current\_state\` остаётся строкой. Требуется массив объектов \`object/state\` и табличный вывод.

\#\#\# Пустые итоговые таблицы

Причина не сводится к aliases. Fallback использует \`extract\_atomic\_items()\`, который классифицирует реплику только в один тип, применяет регулярные выражения и требует строгие слова для \`explicit\_agreement\` и \`commitment\_confirmed\`.

При этом в тематических блоках уже содержатся согласованные подходы, вопросы, ограничения и следующие действия. Пустые массивы решений, вопросов, рисков и задач противоречат содержанию тематических блоков.

Нужен отдельный смысловой LLM extraction pass для итоговых реестров.

\#\# 3\. Дефект \`management\_summary\`

Фактическая ошибка пользователя:

\`\`\`  
LLM generation failed: Ответ не является валидным JSON:  
Expecting ',' delimiter  
\`\`\`

Значит repair/retry либо не поставлен в рабочую ветку, либо не подключён к реальному вызову, либо запускается после места, где provider уже выбрасывает исключение.

Также schema, mapper и renderer не согласованы:

\- schema содержит вложенный \`general\_info\`;  
\- mapper ищет \`protocol\_title\` на верхнем уровне;  
\- schema задаёт массивы \`decisions\_and\_approaches\`, \`critical\_gaps\_and\_risks\`, \`control\_points\`;  
\- mapper не переносит их полноценно в Protocol;  
\- fallback снова зависит от regex atomic items.

Даже schema-valid ответ может потеряться при сборке.

\#\# 4\. Общий дефект шаблонов

Для каждого шаблона существуют четыре независимых контракта:

1\. JSON Schema.

\`\`\`  
schema fixture
