\#\# Дефекты project\_detailed

\#\#\# Потеря ролей участников

В таблице присутствуют имена, но все роли заменены на прочерк.

Текущий renderer читает только поле \`role\`, тогда как LLM может вернуть \`position\`, \`job\_title\` или \`должность\`. Кроме того, список участников LLM может полностью заменить ранее извлеченный список и стереть известные роли пустыми значениями.

\#\#\# Клиент и проект не отображаются

Поля добавлены в \`BatchItem\` и \`Protocol\`, но:

\- не передаются в основной LLM prompt;  
\- назначаются после \`assemble\_from\_llm\_json()\`;  
\- не выводятся renderer-ами двух шаблонов;  
\- доступны не во всех путях добавления файла.

Наличие полей в dataclass не означает, что они попали в документ.

\#\#\# Ключевые итоги стали одним пунктом

Фактический HTML содержит один \`\<li\>\`, внутри которого лежат \`1) ... 2\) ... 3\) ... 8)\`.

Причина: если LLM возвращает одну строку с внутренней нумерацией, renderer оборачивает всю строку одним \`\<li\>\`.

Требуется нормализация в настоящий \`list\[str\]\`.

\#\#\# Тематические блоки остаются длинными абзацами

Renderer создаёт новый \`\<p\>\` только по уже существующим переводам строк. LLM возвращает \`discussion\_content\` одной строкой, поэтому оформление не меняется.

Нужно получать или нормализовать массив смысловых абзацев.

\#\#\# Решения, вопросы, риски и задачи пусты

Таблицы скрыты и заменены сообщениями \`отсутствуют\`, хотя в тематических блоках есть:

\- согласованные подходы;  
\- открытые вопросы;  
\- ограничения;  
\- действия;  
\- ответственные;  
\- даты следующих встреч;  
\- необходимость дополнительной проверки.

Отсутствие всех четырех реестров является дефектом извлечения, а не свойством расшифровки.

\#\#\# Regex fallback недостаточен

Решение попадает в реестр только при \`explicit\_agreement=true\`, задача — при \`commitment\_confirmed=true\`. Одна реплика получает один тип. Смысловые выводы thematic blocks повторно не анализируются.

\#\# Дефекты management\_summary

1\. Участники не заполнены, хотя та же расшифровка даёт участников в \`project\_detailed\`.  
2\. Управленческое резюме пустое.  
3\. Решения, риски и задачи пусты.  
4\. \`key\_results\` и \`control\_points\` сериализуются через \`json.dumps()\` и выводятся как строковое представление списка.  
5\. Schema, mapper и renderer не образуют единый контракт.

\#\# Корневая причина

Нужна единая цепочка:

\`\`\`  
LLM schema  
→ нормализация типов  
→ mapping  
→ общий extraction реестров  
→ merge без потери данных  
→ renderer  
→ contract tests  
\`\`\`

Aliases без отдельного смыслового extraction pass проблему не решают.
