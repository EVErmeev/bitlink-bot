\#\# Фактическое наблюдение

После нажатия основной кнопки «Запустить обработку» открывается окно:

\- «Проверка пройдена успешно»;  
\- «Ошибок не обнаружено».

Это окно не является результатом обработки. Это только modal preflight.

В текущем коде worker запускается только после второго нажатия кнопки «Запустить обработку» внутри окна предстартовой проверки. До этого \`\_do\_start\_processing()\` не вызывается, поток \`QueueController.\_process\_batch()\` не создаётся и pipeline не выполняется.

\#\# Новые блокирующие замечания

\#\#\# BB-CRIT-035 — успешный preflight не запускает обработку и вводит пользователя в заблуждение

Основная кнопка фактически только открывает второе окно и требует повторного запуска.

\#\#\# BB-CRIT-036 — preflight не проверяет сервисы

Текущий preflight проверяет только наличие pending-элементов, путь, существование и размер файла, тип источника и наличие шаблона. Не проверяются LLM, Confluence, Telegram, Newton, Bitlink и возможность записи артефактов.

\#\#\# BB-CRIT-037 — опасный mixed mode

\`BatchItem.dry\_run\` по умолчанию равен \`False\`, а GUI не даёт пользователю управлять dry-run. Возможна публикация mock-протокола в real Confluence или отправка в real Telegram.

\#\#\# BB-CRIT-038 — Settings GUI не переработан

Нет provider modes, LLM settings, Confluence provider, Telegram enabled/mock и dry-run default.

\#\#\# BB-CRIT-039 — нет безопасного dry-run управления из GUI

Пользователь не видит dry-run ни при добавлении файла, ни в параметрах строки.

\#\#\# BB-MAJ-040 — demo banner не учитывает конкретный источник

Для local TXT Newton и Bitlink не нужны, но их mock mode всё равно отображается.

\#\#\# BB-MAJ-041 — \`batch\_done\` отправляется дважды при исключении

Событие добавляется и в \`except\`, и в \`finally\`.

\#\#\# BB-MAJ-042 — реальный GUI E2E не подтверждён

OpenCode сообщил о CLI dry-run, но пользователь проверяет GUI.

\#\# Обязательное целевое поведение

1\. Основная кнопка Start нажимается один раз.  
2\. Выполняется полный source-aware preflight.  
3\. Без ошибок и предупреждений worker стартует автоматически.  
4\. При предупреждениях показывается «Продолжить» / «Отмена».  
5\. При blocking errors запуск запрещён.  
6\. Mock upstream \+ real downstream автоматически переводит строку в dry-run либо блокирует публикацию.  
7\. Первый stage отображается не позднее 500 мс после запуска.  
8\. Итог содержит точные counts, status, error и путь к артефактам.
