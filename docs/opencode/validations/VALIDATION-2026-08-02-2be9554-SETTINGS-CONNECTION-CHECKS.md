\#\# Подтверждённые дефекты

\#\#\# BB-CRIT-092 — LLM worker вызывает несуществующий \`self.root\`

\`SettingsFrame\` не создаёт атрибут \`root\`, но worker-потоки используют:

\`\`\`python  
self.root.after(...)  
\`\`\`

Фактическое исключение:

\`\`\`text  
AttributeError: 'SettingsFrame' object has no attribute 'root'. Did you mean: '\_root'?  
\`\`\`

Следствия:

\- результат \`version\`, \`health\` или LLM smoke-test не возвращается в GUI;  
\- кнопка остаётся disabled;  
\- статус остаётся «Проверка...»;  
\- пользователь воспринимает это как зависание;  
\- ошибка остаётся только в терминале.

\#\#\# BB-CRIT-093 — БИТ.Link, Newton, Confluence и Telegram не используют текущие значения формы

Проверки создают клиентов без аргументов:

\`\`\`python  
BitlinkClient()  
TranscriptionClient()  
ConfluenceClient()  
TelegramClient()  
\`\`\`

Следовательно, проверяются глобальные сохранённые настройки, а не значения, которые пользователь только что ввёл в поля GUI.

Пользователь может изменить token/URL/chat ID, нажать «Проверить подключение» и получить результат по старой конфигурации.

\#\#\# BB-CRIT-094 — mock-режим отображается как успешное подключение

Текущие проверки показывают:

\`\`\`text  
Подключение успешно (mock-режим)  
\`\`\`

При этом внешний сервис не вызывается.

Mock означает демонстрационный режим, а не подтверждённое подключение. Зелёный статус \`SUCCESS\` недопустим.

Корректный статус:

\`\`\`text  
DEMO / MOCK — реальное подключение не проверялось  
\`\`\`

\#\#\# BB-CRIT-095 — БИТ.Link real adapter не реализован, но UI предлагает проверку подключения

\`BitlinkClient.check\_connection()\`:

\- в mock возвращает \`True\`;  
\- в real возвращает только локальный \`\_authenticated\`;  
\- \`authenticate()\` в real без HTTP-вызова устанавливает \`\_authenticated=True\`;  
\- реальные rooms/recordings заканчиваются \`NotImplementedError\`.

До реализации и подтверждения API-контракта UI не может показывать «подключено».

Корректный статус:

\`\`\`text  
NOT\_IMPLEMENTED — real API БИТ.Link отсутствует  
\`\`\`

\#\#\# BB-CRIT-096 — блок Newton для транскрибации не выполняет реальную проверку

\`TranscriptionClient.check\_connection()\` в real проверяет только наличие token/base URL:

\`\`\`python  
return bool(self.token and self.base\_url)  
\`\`\`

Сетевой вызов, health, auth и тестовая транскрибация отсутствуют. Реальный \`transcribe\_video()\` не реализован.

Наличие строк в \`.env\` не является проверкой подключения.

\#\#\# BB-CRIT-097 — Confluence GUI не проверяет конкретную рабочую конфигурацию

REST-клиент умеет выполнить запрос \`/rest/api/user/current\`, но GUI:

\- не передаёт текущие несохранённые Base URL/token/space;  
\- не показывает HTTP status;  
\- не проверяет доступ к Space Key;  
\- не проверяет Parent Page ID;  
\- не проверяет совпадение Parent Page Title;  
\- не различает 401, 403, 404, timeout и TLS error.

\#\#\# BB-CRIT-098 — Telegram проверяет только бота, но не целевой чат

\`getMe\` может пройти, даже если:

\- Chat ID неверный;  
\- бот не состоит в чате;  
\- бот не имеет права отправки;  
\- используется старое сохранённое значение вместо текущего поля.

Для достоверной проверки нужны как минимум \`getMe\` и \`getChat\`, а для полной проверки — отдельная подтверждаемая отправка тестового сообщения.

\#\#\# BB-CRIT-099 — OpenAI LLM проверяется синхронно в Tkinter main thread

\`\_test\_openai\_llm()\` выполняет HTTP и генерацию напрямую из callback.

Следствия:

\- окно может зависнуть на timeout;  
\- кнопка не показывает стадию;  
\- нет отмены;  
\- нет единой диагностики;  
\- exception выводится одной строкой.

\#\#\# BB-MAJ-100 — нет единой модели результата проверки

Каждый блок выводит собственный \`messagebox\`. Отсутствуют общие поля:

\- service;  
\- provider/mode;  
\- stage;  
\- status;  
\- latency;  
\- endpoint/command;  
\- HTTP/exit code;  
\- safe message;  
\- recommendation;  
\- checked\_at;  
\- config fingerprint без secrets.

\#\#\# BB-MAJ-101 — нет статусов \`NOT\_CONFIGURED\`, \`MOCK\`, \`NOT\_IMPLEMENTED\`, \`PASS\`, \`FAIL\`

Сейчас bool \`True/False\` не позволяет отличить:

\- demo/mock;  
\- отсутствие настроек;  
\- неподдерживаемый real adapter;  
\- успешную auth-проверку;  
\- успешную функциональную проверку;  
\- сетевую ошибку;  
\- ошибку прав.

\#\#\# BB-MAJ-102 — кнопки не восстанавливаются после ошибки callback

При исключении до \`\_on\_\*\_result()\` кнопка остаётся disabled. Нет общего \`finally\` на стороне main thread.

\#\#\# BB-MAJ-103 — нет сводной проверки всех подключений

Пользователь не видит, готово ли приложение целиком. Нужна матрица:

| Сервис | Режим | Конфигурация | Подключение | Функциональная проверка | Итог |

\#\#\# BB-MAJ-104 — нет сохранения безопасного отчёта диагностики

Результат существует только в messagebox/status label. Нельзя приложить единый отчёт к проверке или воспроизвести причину ошибки.

\#\# Критерии закрытия

1\. Ни одна mock-проверка не отображается зелёным \`PASS\`.  
2\. Все проверки используют текущие значения формы, даже до сохранения.  
3\. Все внешние вызовы выполняются вне Tkinter main thread.  
4\. Все результаты возвращаются через \`self.after(...)\` или валидный root.  
5\. Кнопки всегда восстанавливаются после success/failure/timeout/exception.  
6\. БИТ.Link и Newton transcription честно показывают \`NOT\_IMPLEMENTED\`, пока real adapter отсутствует.  
7\. Confluence проверяет auth, space и parent page.  
8\. Telegram проверяет bot и chat; тестовая отправка — отдельной кнопкой.  
9\. БИТ Ньютон разделяет version, health и real LLM smoke-test.  
10\. OpenAI выполняет connection и schema smoke-test асинхронно.  
11\. Есть «Проверить все подключения» и сводная readiness-матрица.  
12\. Диагностика копируется и сохраняется без secrets.  
13\. Выполнен ручной Windows E2E через \`start\_app.bat\`.
