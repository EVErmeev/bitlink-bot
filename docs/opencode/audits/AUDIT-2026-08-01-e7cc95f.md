## BB-CRIT-001 — Интеграции работают только как hardcoded mock

**Статус:** OPEN

Все внешние сервисы (`BitlinkClient`, `TranscriptionClient`, `ConfluenceClient`, `TelegramClient`)
реализованы исключительно как mock-заглушки с `self.mock_mode = True`.
Реальные HTTP-запросы отсутствуют.

- `services/bitlink_service.py` — `get_rooms()`, `get_recordings()` возвращают жёстко закодированные словари.
- `services/transcription_service.py` — `transcribe_video()` возвращает статический текст.
- `services/confluence_service.py` — `create_page()` генерирует фиктивный URL.
- `services/telegram_service.py` — `send_notification()` печатает в stdout.

**Требуется:** Реализовать реальные HTTP-адаптеры, настраиваемые через `.env`.
Mock-режим включается только через явный параметр `*_MOCK=true` в `.env`.
При `*_MOCK=false` и отсутствии конфигурации адаптер должен возвращать ошибку.
Приложение не должно незаметно использовать тестовые данные.

## BB-CRIT-002 — LLM-генерация отсутствует

**Статус:** OPEN

Ни один из четырёх шаблонов не вызывает LLM. Контент протоколов формируется:
- `project_detailed`: группировкой фактов через `re.split()` + `lower()`.
- Остальные три шаблона (`management_summary`, `project_standard`, `business_process_discovery`):
  `assemble()` не заполняет контент — оставляет пустые строки.

**Требуется:** Отдельный LLM-слой с конфигурируемым провайдером и промптами из шаблонов.

## BB-CRIT-003 — project_detailed объединяет все факты в одну тему

**Статус:** OPEN

`assemble()` в `project_detailed.py` выбирает все элементы типа `item.item_type == "факт"`,
объединяет их через `join` в один `TopicBlock` с заголовком "Обсуждение (факты встречи)"
и не выполняет тематическую кластеризацию. Темы не разделяются по смыслу.

**Требуется:** Реализовать тематическую кластеризацию — группировку фактов по смысловым
блокам с осмысленными заголовками.

## BB-CRIT-005 — Провал валидации может помечаться успехом

## BB-CRIT-006 — После apply_corrections нет повторной фактологической проверки

**Требуется:** Добавить повторный вызов `validate_facts()` после `apply_corrections()`.

## BB-CRIT-007 — Изоляция источников использует путь вместо SHA содержимого

**Статус:** OPEN

`generate_source_context_id()` в `source_isolation.py`:
```python
seed = source_path or bitlink_recording_id or str(uuid.uuid4())
return hashlib.sha256(seed.encode("utf-8")).hexdigest()[:16]
```
Использует путь к файлу как seed, а не SHA-256 содержимого источника.
Одинаковые файлы с разными путями получат разные `source_context_id`.

**Требуется:** Использовать `source_sha256` (SHA-256 содержимого) как первичный seed.
`source_path` — только fallback при недоступности содержимого.
